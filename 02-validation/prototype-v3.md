## What it tests

_Tie it back to the validation brief: which assumption does this prototype put in front of a user?_

The data being displayed indicates what happened on the app/tool but never explains the next course of action to fix the issues so users end up finding it not useful.

## Context injected (no placeholders)

- **Real user quotes on screen:** “I open it, see twelve charts, and have no idea which one I'm supposed to act on. So I close it.” / “The number I need is in there, but it takes six clicks and three filters to find it.”
- **Domain metrics on screen:** 60% Bounce rate: sessions under 15s with no interaction. / 12 Charts on the default landing view. / 6 clicks To reach the most-requested metric.

## Iteration log (v1 → v3)

| Version | Change | Why |
|---|---|---|
| v1 | Dashboard with various data points | Usability issue outlined as main churn rate reason |
| v2 | More filters: since inception and date range selector | Provide the users with the ability to select which period they want to view the data for |
| v3 | Prototype to test & friction points displayed with course of action | Users want to understand what are the friction points on tools/apps and what should be done to fix it |
